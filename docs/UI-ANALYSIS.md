# 디자인 분석과 구현 범위

기준: 기존 Codex 배포본 `outputs/pipeguide-deploy/index.html`의 화면 구성. 해당 소스나 번들·모델·데이터를 복사하지 않고 디자인 패턴만 재작성했다.

| 화면 패턴 | Next 구현 |
| --- | --- |
| 짙은 청색 배경, 파란 활성 상태, 얇은 테두리 | 독립 CSS 토큰과 반응형 스타일 |
| 상단 브랜드·선박 정보 | PipeGuide NEXT, 새 워크스페이스, 설계 데이터 미연결 |
| 왼쪽 탐색·문제 검토·경로 개선 메뉴 | 동일 뷰포트를 유지하는 UI 모드 |
| 상단 검색, 3D/2D 전환 | 데이터 없음 안내, 입체/평면 방향 전환 |
| 오른쪽 보기 도구 | 방향 초기화·방향 자동 회전·레이어 안내; 모델 확대는 비활성 |
| 하단 배관·장비·공간 탭 | 대상 UI 상태와 미연결 안내 |
| 필요할 때 정보 패널 표시 | 검색 결과 안내·작업 패널·모듈 설정 패널 |
| 실제 선박·검사 결과·경로 표시 | 이번 단계 제외; 빈 WebGL 뷰포트 제공 |

## 화면 코드와 기능 코드의 경계

재작성 대상은 DOM 구성, 색·배치, 선택 상태, 모드 전환, 패널, 키보드와 뷰포트 입력이다. 이전의 GA 좌표, 선박 구조 전역 객체, 선박 메시·치수, PidNet, 검사 규칙, 승인 상태, 경로 계산·적용 코드는 화면의 필수 요소가 아니므로 포함하지 않았다.

오프닝의 회전 선박도 설계 모델과 혼동될 수 있어 이번 UI MVP에는 포함하지 않는다. 기본 진입은 빈 워크스페이스이며, 실제 데이터가 없다는 설명을 표시한다. WebGL에는 UI 방향 표시만 있고 물리 단위·선박·장비·배관이 없다.

## 다음 단계 연결 지점

`src/main.js`는 UI와 어댑터를 조립하는 지점이다. 계약은 `src/modules/contracts.js`, 등록·호출·취소 경계는 `registry.js`에 있다. 현재 등록된 어댑터는 0개다. 실제 도메인 로직이나 예시 설계 데이터를 작성하지 않았다.
